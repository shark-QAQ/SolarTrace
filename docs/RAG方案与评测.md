# RAG 方案与评测

## 1. 检索链路设计

### 1.1 查询理解与改写（`retrieval/rewrite.py`）
对口语化/长尾提问做四级处理：
1. **术语归一（同义替换）**：如「光伏板」→「光伏组件」；「并网申请」→「并网验收要求」。
2. **术语扩展**：命中分布式光伏→追加「分布式光伏发电」；命中并网→追加「并网验收/接入电网」等，扩大召回。
3. **文档类型软提示**：根据问题关键词推断 建设规范/并网政策/前期手续/电价补贴，仅作精排小加成（不硬过滤）。
4. **年份提示**：识别 `20xx` 供策略扩展（预留）。

### 1.2 混合检索
| 路 | 工具 | 作用 |
| --- | --- | --- |
| 稠密 | bge-m3（Ollama `/api/embed`，1024 维） | 语义召回 |
| 词法 | BM25（jieba 分词 + rank_bm25） | 精确命中文号/条款号/规范词 |
召回深度默认各 30，取并集构建候选池。

### 1.3 RRF 融合
对候选在**两路各自榜单中的排名**做 `score = Σ 1/(k+rank)`（k=60），获得与绝对分值解耦的融合序，仅用于候选排序。

### 1.4 两阶段精排（`retrieval/reranker.py`）
- **阶段一**：召回候选池（RRF 排序）。
- **阶段二**：relevance = `0.45·稠密余弦 + 0.35·词法覆盖(含文号/标题命中) + 0.20·BM25归一`，再做 Top-K 截断与门限；
  首条恒保留，防止“有料却空答”。文档类型软提示加 0.05。
- 可选 `cross_encoder`：配置 sentence-transformers + `bge-reranker-v2-m3` 时启用 CE 打分（缺依赖自动回退）。

### 1.5 回表校验（防引用失效）
块内写入 `doc_key`（由 类型/文号/发文机关/标题 派生）。检索命中后回到 DB 的
`doc_key → current_version_id` 映射校验：**仍发布且为当前版本**才保留。归档/过期政策即时从结果消失。

### 1.6 标题感知父子分块
- 父块 = 标题链下的章节段（分组单元）。
- 子块 = 对父块做约 300 字、60 字 overlap 的滑动切分，文本前置章节路径提升命中，metadata 保留 `parent_seq/section_path`。
- 检索单元为子块，命中即定位到具体章节/条文范围，引用精确到“段落”。

## 2. 生成与引用（`services/qa_service.py`）
- 材料格式：`[1] 出处：文号《标题》（类型，机构，年份）；章节：xxx；原文：…`，逐句要求标注 `[n]`。
- System 指令：仅依据材料作答、禁止编造文号/条款、材料不足时明确提示。
- `grounded`：回答中至少出现一个落在材料编号范围内的 `[n]` 标记。
- 无依据：返回“知识库未检索到已发布有效依据”提示而非硬答。

## 3. 评测集与方法

评测集 = 标注问答对：`question + golden_doc_codes(黄金文号) + golden_keywords + category`。

| 指标 | 定义 | 取值口径 |
| --- | --- | --- |
| 命中率@K (hit_rate) | Top-K 中是否出现黄金文号（无文号时按关键词命中计） | 每问 0/1，求均值 |
| Top1 命中 | 首条即为黄金文号 | 每问 0/1，求均值 |
| 上下文召回率 | 黄金关键词在召回 Top-K 文本中的覆盖率均值 | 逐问 keyword recall 求均值 |
| 引用忠实度 | 生成答案中 `[n]` 指向的黄金文号占比（需勾选“生成”，较慢） | 无生成不评分 |

运行快照存入 `eval_runs`（含逐条明细），供回归对比（对比分块/重排/召回参数前后）。

## 4. 演示语料基线（可复现）

| 项 | 值 |
| --- | --- |
| 语料 | 内置 8 篇政策/规范演示摘编 → 38 个片段（标题感知父子分块） |
| 评测集 | 25 题（覆盖 4 大类） |
| 配置 | 确定性重排、Top-5、无生成 |
| 结果 | 命中率@5 = **100%**；Top1 = 72%；上下文召回 = 89.3%；引用忠实度 = 未评测（生成可选） |

> 说明：演示语料为“整理摘编”，问题与文号一一对应，故命中率高；真实文本下的指标用于**回归调优**而非绝对值宣传。

## 5. 调优路径（README/工具已留）
1. 调整 `CHUNK_SIZE/CHUNK_OVERLAP` → 重跑评测对比；
2. 调整 `RECALL_*_TOP_K/RRF_K/MIN_SCORE_KEEP`；
3. 打开 `cross_encoder` 重排或 `LLM_USE_REWRITE`；
4. 在文档库补充正式政策原文重建索引后重跑。
