# 部署与运维

## 1. 目录与启动

### 1.1 开发环境（Windows / Linux 一致）
前置：Python 3.14、uv、Node 18+；Ollama 已装模型（可选，见离线演示）。

```bash
cd backend
cp .env.example .env
uv sync --extra test
uv run python -m app.scripts.seed_demo     # 灌演示语料（幂等）
uv run uvicorn app.main:app --reload --port 8000
```

```bash
cd ../frontend
npm install
npm run dev      # http://localhost:5173
```

### 1.2 Docker 部署（前后端分离容器）
```bash
cd SolarTrace
cp deploy/.env.example .env     # 可改 secret / 模型
docker compose -f deploy/docker-compose.yml up -d --build
# 前端 http://localhost:8080 ；健康检查 http://localhost:8000/api/v1/system/health
```

- 默认 `SOLARTRACE_OLLAMA_BASE_URL=http://host.docker.internal:11434`（访问宿主 Ollama）。
- 若要容器内置：把 Ollama 也容器化并在同一网络，然后改该变量指向其服务名。
- 启用 Qdrant（分布式向量）：`SOLARTRACE_VECTOR_BACKEND=qdrant` 且
  `docker compose -f deploy/docker-compose.yml --profile qdrant up -d --build`。
- 首启 `api` 会执行幂等 `seed_demo`；如无需演示数据可直接删 CMD 中的种子调用。

## 2. 配置清单（backend/.env，前缀 `SOLARTRACE_`）

见仓库根 README §7。生产至少修改：
- `SOLARTRACE_SECRET_KEY`
- `SOLARTRACE_BOOTSTRAP_ADMIN_PASSWORD`（首启建号后立即改密或停用）
- 视规模设 `SOLARTRACE_ENVIRONMENT=production`（隐藏 /docs）
- 需要真实文本：在文档库上传正式政策原文并发布；演示语料仅为摘编样本。

## 3. 数据与备份

| 数据 | 位置 |
| --- | --- |
| 关系库 | `backend/data/solartrace.db`（容器卷 `solartrace-data`） |
| 向量库 | `backend/data/chroma/`（容器卷 `solartrace-data`） |
| 上传原件 | `backend/data/uploads/`（按 `doc{id}_v{ver}.ext`） |
| 日志 | stdout（JSON 或 text），采集侧可落盘/接 Loki 等 |

备份策略：整体备份 `data/` 目录即可原子还原；对账接口可在恢复后 `POST /system/reconcile` 自愈索引。

## 4. 运维动作

| 动作 | 入口 |
| --- | --- |
| 健康/就绪 | `GET /api/v1/system/health`、`/system/ready` |
| 运行指标 | `GET /api/v1/system/stats`、`/system/runtime` |
| 索引对账 | 前端“文档库 → 对账索引”或 `POST /system/reconcile` |
| 索引操作流水 | `GET /api/v1/system/index-ops` |
| 审计 | `GET /api/v1/system/audit`（admin） |
| 检索质量回归 | 前端“RAG 评测”跑分；历史运行留存对比 |

## 5. 安全清单

- [ ] 更换 `SECRET_KEY` 与初始管理员口令
- [ ] 生产仅开放 443/80 与必要的 8000；DB/向量/Ollama 不暴露公网
- [ ] 通过 `SOLARTRACE_CORS_ORIGINS` 收紧跨源白名单
- [ ] 上传类型与大小由服务端白名单限制（已内置 .pdf/.docx/.md/.txt，≤20MB）
- [ ] 定期备份 `data/`；重要写操作在审计中留痕
- [ ] 合规：正式政策入库请使用受权文本与版权合规来源

## 6. 常见问题

| 现象 | 处理 |
| --- | --- |
| 检索返回空 / 服务 503 | 查 `/system/ready`：DB、向量、BM25 是否就绪；`/system/runtime` 看组件健康 |
| 生成不可用但检索可用 | 确认 Ollama 运行且 `llm_model` 存在；可暂设 `SOLARTRACE_LLM_PROVIDER=fake` 走离线演示 |
| 无 GPU/内存紧 | 设 `SOLARTRACE_EMBEDDING_PROVIDER=hash`（离线词法+哈希语义退避）；检索调试仍可演示 |
| 重新灌语料不生效 | seed 幂等按文号/校验和跳过；如需强制重建，先归档文档再用脚本重灌或手动重发版本 |
| 改了分块/重排参数 | 重跑发布（重建索引）+ 跑评测集对比 |
| 评测接口报 `no such column: citation_precision` | 旧库 `eval_runs` 列名为 `faithfulness`（该指标已更名，口径为引用查准）。执行 `ALTER TABLE eval_runs RENAME COLUMN faithfulness TO citation_precision;`（SQLite 3.25+ / PG 10+），或直接重建该表——快照可重跑生成 |
