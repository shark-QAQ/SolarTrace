# 需求设计书 · SolarTrace（光溯）

| 项 | 内容 |
| --- | --- |
| 文档 | SolarTrace 需求设计书 V1.0 |
| 定位 | 光伏电站建设政策与规范智能问答平台（工业级 RAG） |
| 读者 | 产品 / 算法 / 交付 |

## 1. 背景与目标

面向光伏电站建设场景，政策与规范检索效率低、人工翻文档易遗漏、口头引用易出错。
平台将**分布式光伏、并网政策、建设/验收规范、前期手续、电价结算**等知识文档统一入知识库，
回答“提问即得带原文出处、可点开原文的精准结论”，并持续用评测集度量检索质量。

核心目标（对齐经验教训）：
1. **找得准**：混合检索 + 两阶段精排 + 查询改写，降低表达差异带来的召回损失。
2. **不编造**：回答强制绑定来源，检索命中后回表校验文档有效性，杜绝引用失效/过期政策。
3. **可运营**：文档版本化建索引（发布即建、退稿即清、可对账）、问答留痕、RAG 评测回归。

## 2. 用户与角色

| 角色 | 能力 |
| --- | --- |
| 访客 viewer | 问答、检索调试、查看文档与评测结果 |
| 编辑 editor | 上传/发布/归档文档、对账索引、运行评测 |
| 管理员 admin | 编辑全部能力 + 用户与角色管理、审计查看 |

## 3. 功能需求

### 3.1 智能问答（Q&A）
- SSE 流式输出（`meta → delta* → done|error`）。
- 输入检索到的 Top-K 材料 + 接地指令；要求逐句标注 `[n]`，禁止编造文号/条款。
- 引用区展示：文号·标题·章节路径·命中片段·精排得分。
- 知识库无可靠依据时明确提示“未覆盖/已失效”，不得硬答。

### 3.2 检索调试
- 结构化展示：原始问题 → 改写结果（规范化/扩展/类型提示）→ 精排后的 Top-K（章节/片段/得分）。

### 3.3 文档库与版本管理
- 上传 PDF/DOCX/Markdown/TXT，解析保留标题结构。
- 同文号/同名自动挂新版本；可显式指定目标文档追加版本。
- **发布建索引**：物理清理旧版向量 → 原子写入新版块 → 刷新 BM25 → 记录索引操作。
- **归档退稿**：删除该文档全部向量；检索层另做回表双保险。
- **对账**：扫描 DB 与向量库差异自动修复；孤儿向量清理。

### 3.4 评测闭环
- 标注评测集（问题 → 黄金文号/关键词/类型）。
- 指标：命中率@K、Top1 命中、上下文召回率、引用忠实度（可选生成）。
- 每次运行留存逐条明细，支持回归对比。

### 3.5 权限与审计
- JWT 登录；三角色 RBAC；停用账号。
- 登录/上传/发布/归档/改角色/评测等写操作全程审计。

### 3.6 系统
- `/health`（存活）、`/ready`（DB/向量/BM25/嵌入/生成探活）、`/stats`（各域计数）。

## 4. 非功能需求

| 维度 | 要求 |
| --- | --- |
| 性能 | 检索链路（改写+双路召回+精排+回表）目标 P95 < 1s；生成流式低首字延迟 |
| 安全 | 密钥环境化、密码 bcrypt、JWT 过期、无越权写接口、上传白名单与大小限制、输入长度限制 |
| 可观测 | JSON 日志、x-request-id、索引操作流水、问答日志（模型/耗时/grounded） |
| 一致性 | “索引与文档库一致”可通过对账接口验证与修复 |
| 交付 | Docker 一键部署（前后端隔离容器）；开发环境 5 分钟内可起 |

## 5. 验收口径（红线）

1. 现场演示闭环：上传政策 → 发布自动建索引 → 问答带 `[n]` 引用并能点开原文片段；
2. 归档某政策后，再次提问该主题**不得再引用已归档条目**（回表校验生效）；
3. 检索/问答全链路可观测：检索调试页能解释“为什么召回它”（重写串/章节/得分）；
4. 单元+集成测试离线可复现，`pytest` 全绿。

## 6. 术语

- 父块/子块：标题层级切父段，约 300 字 + overlap 子块入库；子块保留章节路径用于标题感知。
- 回表校验：检索命中后以 doc_key 回到 DB 比对“文档仍发布且为当前版本”。
- doc_key：由 类型/文号/发文机关/标题 确定性派生的文档稳定主键。
